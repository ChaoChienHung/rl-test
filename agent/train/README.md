# Train-only Jev controller pilot

The completed first pilot used exactly 5,500 FEVER train IDs from `verifier/data/train/sft/fever-oracle-direct-5500/labeled_prompts.jsonl`. Its selection and citation heads have each completed 5,500 episodes and were evaluated on the frozen 900 dev claims. The **new citation SFT → RL experiment** fixes a disjoint, label-balanced 3,000/2,500 split in [`agent/data/controller_split/sft3000-rl2500/manifest.json`](../data/controller_split/sft3000-rl2500/manifest.json). Verify it with `python -m agent.data.build_controller_split --check`. The 900 dev claims are evaluation only.

`agent/train.sbatch` has four phases:

1. `PHASE=rollouts` retrieves evidence and saves three stochastic Qwen outputs for every fixed 10-sentence chunk. It does not choose a controller action. Output: `agent/data/train_rollouts/<model>/<condition>/<run>/`, Git-ignored.
2. `PHASE=sft_data` uses the existing 5,500-claim chunk rollout. `SFT_SUBSET=sft` builds the fixed 3,000-claim warm-up; `SFT_SUBSET=all` builds the 5,500-claim SFT-only control, reusing the 3,000 completed episodes and generating only the other 2,500. A 0.5 heuristic selects one valid-citation draw per chunk **only to fix the pooled input**; the heuristic is not the SFT action label. Qwen samples three new pooled outputs for each unreused claim. Hindsight gold evidence coverage and verifier outcomes produce high-margin STOP/RETRY labels; ambiguous decisions are omitted. States saved for training contain only the current draw and cited text, never gold or future draws. Output: `agent/data/controller_sft/citation-gold-margin0p2-{3000,5500}-samples/run1/`, Git-ignored. `episodes.jsonl` can resume after an interrupted data job; `manifest.json` appears only when all requested claims finish.
3. `PHASE=sft` fits only the RSI-Jev option scorer on these high-margin citation labels. It balances rare STOP/RETRY classes within each stage and saves `epoch-1`, `epoch-2`, and final scorer heads. `SFT_SUBSET=sft` writes `agent/experiments/jev-sft-citation-from-rsi-v2p1-3000-samples/runs/<run>/`; `SFT_SUBSET=all` writes the 5,500-sample SFT-only control under its own configuration.
4. `PHASE=rl` runs `CONTROLLER_VARIANT=citation` (learn STOP/RETRY, discard RETRY draws, automatically keep valid citations from the STOP draw) or `selection` (learn STOP/RETRY and KEEP/DROP on every visited draw). The selection policy sees the current verifier output and its own previously kept citations from this chunk; DROP can remove a previous KEEP. It does not see uncited retrieval sentences or previous verdicts. Each chunk's final saved set is pooled for three new stochastic Qwen verifier draws. The controller can stop after draw 1 or 2; if it reaches draw 3, the same majority-verdict/confidence rule as validation picks the final output. The new split defaults to the fixed 2,500 RL IDs; the completed historical pilot used all 5,500 IDs.

The new `PHASE=rl` defaults to the fixed **2,500 RL IDs**. `RL_INIT_HEAD=<SFT scorer.pt>` continues from the 3,000-claim SFT head; the initial head is also the KL reference. A fresh run name is required for each arm. `REWARD_MODE=absolute` uses **correct STOP +1, wrong STOP −1, correct RETRY −1, useful wrong RETRY +1.5, futile wrong RETRY −1**, plus the existing outcome/evidence terms and 0.05 per extra draw. A useful RETRY means the selected later verifier verdict actually becomes correct; merely retrying an error earns no bonus. The old 5,500-episode pilot used correct RETRY −1.5 and useful wrong RETRY +0.25; its recorded metadata remains unchanged. New settings are explicit in each run manifest; `CORRECT_RETRY_PENALTY` and `USEFUL_RETRY_CREDIT` apply to the absolute mode. Leaving `RL_INIT_HEAD` unset still permits an RL-only control, but the scheduled comparison below uses the shared SFT starting head for both reward modes.

`REWARD_MODE=relative_stop` is a separate continuation from the **same SFT-only head**. For each RL claim it compares the policy's final verdict, pooled citation quality, saved citation set and simulated call cost with an always-first-STOP counterfactual on that claim. The counterfactual stops on the first draw of every chunk, pools those first-draw citations, and uses the first pooled Qwen sample. The reward is policy utility minus counterfactual utility; it omits the absolute mode's direct STOP/RETRY bonus. A policy that always stops on first draws gets exactly zero incremental reward. If the two policies produce the same citation pool, the baseline reuses the policy's first pooled draw. Different pools require three additional **actual** pooled Qwen generations to match the three-draw sampling setup; these are reward-computation costs, not simulated controller calls. Gold and counterfactual outcomes are used only for training reward and remain outside controller state. The relative reward can be sparse because most first pooled verdicts are already correct.

The SFT labels are **hindsight-derived training targets, not uniquely correct gold actions**. For chunks, partial overlap with a FEVER gold evidence set earns partial credit, while NEI or a chunk with no annotated gold is omitted from local action supervision. For pooled draws, the comparison uses verdict correctness, evidence credit, extra-call cost, and the new asymmetric STOP/RETRY feedback. FEVER annotations may omit valid evidence and later stochastic draws are not predictable from the current state. Inspect the `label_counts` manifest before training; a class with zero examples aborts SFT. Do not choose margins or reward weights by repeatedly tuning on the frozen 900 dev claims.

In the historical 5,500-claim citation run, the first pooled verifier verdict was correct for 4,588 claims (83.4%), and the controller both stopped on that draw and got the verdict right for 4,399 (80.0%). Of the 912 wrong first draws, only 247 had a correct verdict among the next two candidates (27.1% of wrong first draws, 4.5% of all claims). These are descriptive figures for that run, not the eventual SFT label proportions: SFT also filters for high margins, evidence quality, and missing gold within a chunk. Keep reward coefficients fixed across examples; SFT class weights address action imbalance. RL-only and SFT→RL share the same 2,500 RL IDs and reward, but the latter has seen 3,000 additional SFT claims, so their difference measures the value of that warm-up under this data budget, not equal-total-data superiority.

On the fixed 2,500 RL IDs, the historical first pooled draw is verdict-correct in 2,091 claims (83.64%). Always STOP therefore averages `2 × 0.8364 − 1 = +0.6728` on the absolute reward's **action term alone**; evidence and terminal terms add further reward. This is a reason to compare against a constant policy, not proof that positive raw reward itself breaks policy-gradient training. Preserve the absolute run and its metadata as the control. The relative run changes only the RL reward: both start from the same 3,000-claim SFT checkpoint, claim IDs, seed, verifier and evaluator. The separate **5,500-claim SFT-only** control uses the same total claim budget as the two-stage arms. Evaluating the 3,000-claim warm-up checkpoint is optional but helps attribute second-stage gains.

Only the RSI-Jev option scorer is updated; the language tower is frozen. The selected pooled verdict contributes +1 when correct and -1 when wrong. Pooled-verifier citations receive half of the best FEVER gold-set overlap score, including a 0.25 complete-set bonus and a modest off-gold penalty. The **final unique saved set** receives the same type of gold-set score, weighted by 0.25, exactly once per claim. A KEEP during RETRY gives no immediate reward; if the ID is dropped later, it contributes nothing to the final set score. Missing annotated gold evidence lowers coverage; saving off-gold citations incurs a smaller penalty. The first two pooled STOP/RETRY actions receive mean feedback with the coefficients stated above. Each extra chunk or pooled draw costs 0.05. The forced third draw has no STOP/RETRY action feedback. FEVER annotations may omit valid evidence, so an off-gold citation is not declared false. The objective has an EMA baseline, optional KL to the frozen initial scorer, and entropy regularization. `replay_env.py` defines reward helpers; `train_jev_rl.py` runs train-only episodes.

From the repository root on SoC, after checking `sinfo` and installing RSI-Jev in `.venv` with `python -m pip install --no-cache-dir -r agent/requirements.txt` (set `TMPDIR="$HOME/.pip-tmp"` first; see the root README):

```bash
# Submit only after verifying the SoC partition, GPU, time limit and existing source rollouts.
data3=$(sbatch --parsable --export=ALL,PHASE=sft_data agent/train.sbatch)
sft3=$(sbatch --parsable --dependency=afterok:$data3 \
  --export=ALL,PHASE=sft,SFT_SUBSET=sft,RUN_NAME=run1 agent/train.sbatch)
data55=$(sbatch --parsable --dependency=afterok:$data3 \
  --export=ALL,PHASE=sft_data,SFT_SUBSET=all agent/train.sbatch)
sft55=$(sbatch --parsable --dependency=afterok:$data55 \
  --export=ALL,PHASE=sft,SFT_SUBSET=all,RUN_NAME=run1 agent/train.sbatch)

head3=agent/experiments/jev-sft-citation-from-rsi-v2p1-3000-samples/runs/run1/artifacts/checkpoints/scorer.pt
head55=agent/experiments/jev-sft-citation-from-rsi-v2p1-5500-samples/runs/run1/artifacts/checkpoints/scorer.pt
absolute=$(sbatch --parsable --dependency=afterok:$sft3 \
  --export=ALL,PHASE=rl,CONTROLLER_VARIANT=citation,REWARD_MODE=absolute,RL_INIT_HEAD=$head3,RUN_NAME=run1 agent/train.sbatch)
relative=$(sbatch --parsable --dependency=afterok:$sft3 \
  --export=ALL,PHASE=rl,CONTROLLER_VARIANT=citation,REWARD_MODE=relative_stop,RL_INIT_HEAD=$head3,RUN_NAME=run1 agent/train.sbatch)

dev=agent/data/evidence_batches/sft-direct-from-base-qwen3p5-2b-5500-samples/direct-cap160/stochastic-3-draws-per-chunk-900-claims
absolute_head=agent/experiments/jev-rl-citation-from-sft3000-rsi-v2p1-2500-samples/runs/run1/artifacts/checkpoints/scorer.pt
relative_head=agent/experiments/jev-rl-citation-from-sft3000-rsi-v2p1-relative-stop-2500-samples/runs/run1/artifacts/checkpoints/scorer.pt
eval_sft=$(sbatch --parsable --dependency=afterok:$sft55 \
  --export=ALL,EVAL_METHOD=rsi_jev_evidence_selection_baseline,JEV_SOURCE_RUN=$dev,JEV_TRAINED_HEAD=$head55,RUN_NAME=run1 agent/eval.sbatch)
eval_absolute=$(sbatch --parsable --dependency=afterok:$absolute \
  --export=ALL,EVAL_METHOD=rsi_jev_evidence_selection_baseline,JEV_SOURCE_RUN=$dev,JEV_TRAINED_HEAD=$absolute_head,RUN_NAME=run1 agent/eval.sbatch)
eval_relative=$(sbatch --parsable --dependency=afterok:$relative \
  --export=ALL,EVAL_METHOD=rsi_jev_evidence_selection_baseline,JEV_SOURCE_RUN=$dev,JEV_TRAINED_HEAD=$relative_head,RUN_NAME=run1 agent/eval.sbatch)
echo "data3=$data3 sft3=$sft3 data55=$data55 sft55=$sft55 absolute=$absolute relative=$relative eval_sft=$eval_sft eval_absolute=$eval_absolute eval_relative=$eval_relative"
```

RL runs write `manifest.json`, `episodes.jsonl`, and `artifacts/checkpoints/scorer.pt` plus `scorer.json` metadata; SFT runs write `manifest.json`, `train_metrics.jsonl`, and per-epoch/final scorer checkpoints. Checkpoint weights are Git-ignored. Use a new run name for every attempt. Evaluate SFT-only, RL-only, and SFT→RL heads on frozen dev only after the labels and reward weights are fixed, by setting `JEV_TRAINED_HEAD` for `agent/eval.sbatch`. With `EVAL_METHOD=rsi_jev_evidence_selection_baseline`, read `metrics.json`'s `primary_trained_policy` and `primary_trained_quality`: the selection head is evaluated as `jev` (STOP/RETRY plus KEEP/DROP), while a citation head is evaluated as `jev_citation` (Jev STOP/RETRY at chunk and pooled stages, automatic retention of valid STOP citations). Do not use the full `jev` arm as the citation head's primary result; that head did not train KEEP/DROP.

Both training and validation use the same pooled-stage action budget and final-selection rule. Training samples actions from the trainable head; validation chooses the head's top action. Training generates all three pooled candidates for each episode but charges its **simulated** extra draws in the reward. The full 5,500-claim rollout and training run can be long; measure a small train-only pilot before scheduling the complete run.
