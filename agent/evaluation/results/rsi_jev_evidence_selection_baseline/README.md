# STOP/RETRY with evidence KEEP/DROP

This is a separate validation experiment from [`rsi_jev_retry_baseline`](../rsi_jev_retry_baseline/README.md). Both read the same frozen FEVER dev/validation 900-claim, three-draw-per-chunk source. The controller sees the claim, verifier verdict/format/confidence, and **only the sentence text and global ID actually cited by observed verifier draws**. It does not see uncited retrieved sentences, gold, future draws or final Qwen outputs. The source verifier prompt numbers E1–E10 locally within each chunk; controller states add a continuous retrieval E number and the stable `Page:line` ID. The existing Qwen draws need no rerun.

On **each draw**, the controller sees only that draw's verifier output: verdict, format, confidence, and the text and IDs of sentences that verifier cited. It first chooses STOP/RETRY. RETRY discards this draw and its citations. On STOP, Jev can choose KEEP/DROP for each cited sentence; the fixed keep-all rule instead saves every valid citation from this STOP draw. The full 10-sentence chunk, uncited sentences, older draw text, gold, and later draws are hidden. Saved citations from the STOP draw of each chunk are united in a set after every chunk has been visited. After the third draw STOP is forced, but KEEP/DROP remains available. The final evidence set is restored to retrieval order and passed to fresh stochastic pooled Qwen verifier draws. Jev's question explicitly discourages keeping irrelevant or redundant citations. The fixed heuristic uses a 0.5 verdict-token confidence rule for STOP/RETRY.

After all chunks, Jev also emits its own `ACCEPT`/`REJECT`/`NEI` judgment from the saved evidence and observed chunk summaries. This is **record only**: `jev_terminal_verdict` accuracy and disagreement with the final verifier are reported separately. The main final prediction and FEVER score **always** come from a new Qwen verification on the pooled saved evidence. The evaluation precomputes three fresh, stochastic Qwen draws from that same pooled input. Jev sees one pooled verifier output at a time and can STOP or RETRY up to two times; the heuristic uses its confidence threshold for the same action. An early STOP uses **that draw's output**. If neither policy stops by the third draw, choose the majority verdict among the three; if all differ, use the highest verdict-token confidence. For a repeated winning verdict, select its highest-confidence output. These pooled draws go to `pooled_samples.jsonl` in the evaluation run, separate from the precomputed chunk source. Stopping early changes simulated call cost; precomputing all three changes actual call cost, and both are reported.

The evaluator also reports three single-component arms against the same heuristic: `jev_chunk_stop` changes only chunk STOP/RETRY, `jev_keep` changes only cited-sentence KEEP/DROP, and `jev_pooled_stop` changes only pooled STOP/RETRY. `jev` changes all three. `metrics.json` has each arm under `component_ablations` and `policies`. Pooled draws are cached per distinct selected evidence set within a claim, so arms with the same evidence share identical Qwen outputs. Extra evidence sets can increase the actual GPU calls for this comparison; `actual_new_final_qwen_calls` records the total. The controller never sees gold or future verifier draws.

Run from the SoC repo root after the three-draw validation source exists and RSI-Jev is installed:

```bash
JEV_SOURCE_RUN=agent/data/evidence_batches/sft-direct-from-base-qwen3p5-2b-5500-samples/direct-cap160/stochastic-3-draws-per-chunk-900-claims \
EVAL_METHOD=rsi_jev_evidence_selection_baseline RUN_NAME=full900-run1 \
  sbatch --time=1-00:00:00 --export=ALL agent/eval.sbatch
```

For an initial pipeline check, set `PILOT_CLAIMS=30` and a distinct `RUN_NAME`, for example `pilot30-run1`, in the same command. This uses the first 30 frozen source rows after validating the full source. The run's `manifest.json` records `source_n_claims`, `evaluated_n_claims`, and `pilot_subset`; a 30-claim metric is exploratory and must not be presented as the full 900-claim result.

Results go to `agent/evaluation/results/rsi-jev-evidence-selection-baseline/runs/rsi-jev-v2p1-qwen3p5-2b/keep-drop-direct-cap160/<run>/`. Read `decisions.jsonl` for chunk actions and KEEP IDs; `pooled_samples.jsonl` for the new three-draw final-verifier candidates; `predictions.jsonl` for pooled STOP/RETRY, the chosen final verifier output, and Jev's record-only terminal verdict; `metrics.json` for accuracy, FEVER, evidence F1, actual and simulated call costs, controller hindsight errors, duplicate keeps removed, and gold-set coverage. Gold-set coverage is post-hoc and is not shown to the controller. The run does **not** train Jev. To evaluate a scorer head trained on FEVER train only, set `JEV_TRAINED_HEAD` to its `scorer.pt` path and use a new `RUN_NAME`.
