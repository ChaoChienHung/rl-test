# Fixed-chunk STOP/RETRY: heuristic versus RSI-Jev

This evaluation reads the completed three-draw dataset for the frozen 900 FEVER dev claims. For each fixed group of up to 10 retrieved sentences, a controller sees the claim, the verifier's verdict/format/confidence and **only the sentences actually cited by observed verifier draws**. Uncited retrieved sentences and the verifier's raw completion are hidden. It chooses `STOP` or `RETRY`. `STOP` saves the latest output's valid citations for later; `RETRY` discards that output and samples the **same input** again. Every group is still visited. At most two retries are possible per group; the third output is a forced stop. After all groups, their saved citations are pooled in retrieval order and passed to a fresh deterministic final Qwen verifier. The final evidence pool is not capped at 10 sentences. The source Qwen prompts used local E1–E10 within each chunk; controller states show continuous retrieval E numbers plus stable `Page:line` IDs, avoiding ambiguity without regenerating the completed source.

The **Jev question** is embedded as `QUESTION` in [`eval_rsi_jev_retry_baseline.py`](eval_rsi_jev_retry_baseline.py) and copied into each result's `manifest.json`. It explicitly says that STOP retains citations for the later final judgment, RETRY reuses unchanged evidence, and automatically trusting every citation is not reasonable. Jev does not edit the verifier's citations; it accepts or rejects the current output. Fixed heuristic thresholds **0.3, 0.5, 0.7** are all evaluated on the same candidates: STOP requires a valid `SUPPORTED`/`REFUTED` output with finite verdict-token confidence above the threshold and no citation of every sentence in a group of at least four. These thresholds are specified before inspecting the new controller results. This is a fixed-rule versus **zero-shot** controller comparison, not trained Jev or an RL result.

Controller input excludes gold, correctness, FEVER score, later draws and final Qwen results. The Jev run's `decisions.jsonl` records per-group choices for every policy. Each policy's `predictions.jsonl` and `metrics.json` record fresh final outputs, accuracy, FEVER, evidence F1, recall, extra draws, citation counts, forced stops, and call costs. A forced stop can still retain an invalid or overinclusive output; the count is reported separately. Simulated policy call cost is distinct from the actual three-draw precomputation cost. The Jev metrics also give the exact count of chunks where verdict, citations, or either disagree across the three source draws.

Install RSI-Jev in the SoC virtual environment if needed, then submit from the repository root:

```bash
source .venv/bin/activate
python -m pip install "rsi-jev @ git+https://github.com/Shanghua-Gao/RSI-Jev"
JEV_SOURCE_RUN=agent/data/evidence_batches/sft-direct-from-base-qwen3p5-2b-5500-samples/direct-cap160/stochastic-3-draws-per-chunk-900-claims \
EVAL_METHOD=rsi_jev_retry_baseline RUN_NAME=full900-run1 \
  sbatch --time=1-00:00:00 --export=ALL agent/eval.sbatch
```

Check current `sinfo` time/resource limits first. The Jev output is `agent/evaluation/results/rsi-jev-retry-baseline/runs/rsi-jev-v2p1-qwen3p5-2b/stop-retry-direct-cap160/<run>/`. Each threshold has its own matching directory under `agent/evaluation/results/heuristic-retry-threshold-0p3/`, `heuristic-retry-threshold-0p5/`, and `heuristic-retry-threshold-0p7/`. The job shares a new final Qwen call when policies choose identical citations. `RESULT_DIR` selects the Jev run directory; heuristic runs use its final three path components below `agent/evaluation/results/`. A result directory is never overwritten. The three-draw source is Git-ignored and must already exist on SoC. The frozen 900 dev claims are the **validation/evaluation set**; this script does not train a controller. Comparing thresholds on this set is exploratory. After choosing a threshold, assess the final selected policy on a separate untouched holdout before claiming an unbiased test result.

Set `JEV_TRAINED_HEAD=<train-run>/artifacts/checkpoints/scorer.pt` and a new `RUN_NAME` to evaluate a head trained only on the 5,500 FEVER train claims. See [`agent/train/`](../../../train/README.md). The trained-head run uses the same saved validation draws and final verifier definitions.

## Controller diagnostics

Each prediction records the selected draw for every chunk and a separate `controller_diagnostics` object. `metrics.json` aggregates how often the policy stopped on draw 1 or 2, reached the forced third draw, retried after a globally correct verifier output, stopped early on a globally wrong output, and ended wrong after retrying a correct output. It also counts avoidable wrong selections when at least one of the three precomputed draws was globally correct, cases with no correct candidate, complete reachable gold evidence saved, excess whole-chunk citations, and call cost. The paired final verifier metrics are reported separately. These diagnostics use gold and unobserved future draws **after** the policy decisions; they are not online action labels or a controller accuracy rate. A chunk may not contain enough evidence to justify the claim's global FEVER label.
